
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：部门名 / 院系名 / 活动名 / 项目名 / 人名；涉及行业产品、模型或机构时，也要点明来源或正文明确给出的主体。
2. 原标题已经清楚点出主体的：保持原意，不要为改写而改写；英文标题译成中文时保留核心含义。
3. 原标题只是编号 / 口号 / 版本号 / 没信息量的 teaser（如 "第 74 期"、"重磅"、"v2.1.159"、"Day 1"）时，结合【来源】和正文把主体补进标题。例：原标题 "余瑞璜大讲堂（七十四）" + 正文主题 → "余瑞璜大讲堂第七十四期讲材料与 AI 逆向设计"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体部门或院系时，用上位词（如"学校""相关院系"）兜底；没点出具体型号时，用上位词（如"开源模型"）兜底。绝不凭"常识"或"行业常识"编一个具体部门、院系、型号、版本或数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：通知 / 预告 / 解读 / 综述 / 表彰，以及 How / Why / Guide / Analysis / Review / Benchmark 这类解释、分析、教程或评测标题，都必须保留原类型；不能因为正文谈到一项已经发布的安排、成果或既有产品，就改写成“发布 / 推出 / 立项 / 上线 / 开源”。只有原标题明确宣布了发布、通知、立项或表彰，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的部门、院系、活动名、产品或机构。
   例：原标题 "关于 2026 年秋季学期选课的通知" → 保持通知类型，可补主体为 "教务处发布 2026 年秋季学期选课通知"，但不能写成 "教务处调整选课制度"。
   例：原标题 "How GPT-5.6 fuses frontier intelligence with frontier efficiency" → "GPT-5.6 如何兼顾前沿智能与效率"，不能写成 "OpenAI 发布 GPT-5.6"。
   例：一篇回顾某场讲座的综述 → 标题写讲座内容与讲者，不能写成举办讲座的发布口径。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“At DevDay, we introduced …”“Last week we launched …”“上周我们发布了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项能力是现在才开放或新增，才对那一项用对应动作。
   例：原文说明产品此前已发布、本文只演示其用法，标题写这次演示，不写成“本次发布”。
